# FABFORGE — Flesh and Blood TCG, played against an AI

A browser implementation of Legend Story Studios' **Flesh and Blood**, 1v1 against a computer
opponent. Eighth in a series. **Read `HANDOFF.md` first**; it is the only document you have to
read. `PLAN.md` owns every decision and the dated Status.

## The regime — decided, not to be re-litigated

**This is a reproduction, and fidelity is the product.** A divergence from printed behaviour is a
defect to fix, never a design choice.

1. **LSS owns the rules.** `docs/rules.md` is a citation index into the **Comprehensive Rules
   v2.15.0 (2026-09-29)**, kept in gitignored `scratch/rules/`. Every engine rule names the
   section it implements in a comment: `// CR 7.3.2a`. When a card and the engine disagree, read
   the rule and fix the engine.
2. **LSS owns balance.** There is no `BALANCE.md`. Printed numbers are never tuned.
3. **Printed text on the face, verbatim.** Compiled abilities drive play; the face shows the print.
4. **Nothing playable contains content that does not work correctly.** A card the compiler cannot
   read in full is `un` and validation refuses it from any registered deck; `data/defects.js`
   hides a card that misbehaves.
5. **1v1 against the AI.**

## The hard rules

1. **No build step.** Plain browser JS, IIFEs on one `window.FAB` namespace, script order declared
   in `index.html`. Runs from `file://` and from `node tools/serve.mjs`.
2. **The engine surface is exactly `legalActions(s)` / `apply(s, action)` / `isTerminal(s)`**, plus
   `whoActs(s)`. `apply` deep-copies. Never mutate a state in place.
3. **Every UI affordance derives from `legalActions`, and every number the UI shows comes from the
   engine** (`FAB.attackPower`, `FAB.defenseOf`, `FAB.powerOf`, `FAB.costOf`). The UI derives nothing.
4. **One queue of invocations is the control flow.** An effect runs on a copy; a question discards
   the partial run and the answer re-runs it. A pending head owns the game.
5. **The stack and priority are CR 1.11 / 3.15**: both pass, then the top layer resolves or the
   step ends. A reactive window is just priority held by the other seat.
6. **The combat chain is its own structure** with the CR 7 steps: layer, attack, defend, reaction,
   damage, resolution, close.
7. **Cards are data, compiled from printed text** by `tools/build-cards.mjs`. Every compiler
   pattern is anchored to the whole sentence. New op = handler in `js/ops.js` + a compiler pattern.
8. **Seeded RNG; every shuffle and roll happens inside `apply`.**
9. **No silent fallbacks.** Neither `if (!FAB.x)` nor `FAB.x || {}`. A missing dependency throws.
10. **NEVER ASSUME A CHOICE.** `FAB.ask` has no auto-take path. Which card to pitch, a single legal
    target, the order pitched cards return to the deck: the player is asked. Not asked, because
    not a choice: "this", "all of", indistinguishable cards, and a window with nothing legal in it.
11. **OPEN INFORMATION IS A RULE.** Every public zone has a viewer; everything revealed, pitched,
    discarded or destroyed is named in the log. The opponent's hand, deck and face-down arsenal
    show counts only.
12. **One door per rule**: `FAB.ask` (choices), `payRes` (pitching), `FAB.dealDamage` (damage and
    prevention), `FAB.attackPower` / `FAB.defenseOf` (numbers).
13. **Every prompt says what it is about**: the source card, the numbers, what declining does.
14. **Verify in the real browser.** Every UI commit says what was checked on the real page.
15. **Playable first.** Tests protect a working build; they are not the product.

## Registers

| File | Holds |
|---|---|
| `PLAN.md` | every decision, with a dated Status. No other file states one. |
| `DEVIATIONS.md` | rules the engine does not yet keep — standing bugs, each naming its CR section |
| `TODO.md` | wanted improvements to things that already work |
| `data/defects.js` | cards that do not behave as they read — hidden from the player |

## Layout

```
index.html                 the entry point; its script list is the load order
js/                        ns, engine, ops, ai, then the interface
data/cards.js decks.js     GENERATED by tools/build-cards.mjs — never edit by hand
data/defects.js            the gate
tools/                     all .mjs, no dependencies
docs/rules.md rights.md takedown.md
scratch/                   gitignored: rules text, card dataset, decklist pages
```
